## v12.0.0: games, background actions, options, program-location reset
**Why**: Minecraft and Roblox shift lock capture the mouse (raw/relative input), so `MouseMove`/`Click x,y` (SetCursorPos) do nothing there. New group **Games** (c:'mouse'): `gmove` (NexoMoveBy), `glook` (NexoLook, smooth camera turn in N steps), `gclick` (NexoGameClick with hold time) - all via `DllCall("mouse_event", MOVE 0x1 / button flags)` helpers in HELPERS (added only when used). The existing `holdms` block (hold key N ms) is the slow key tap games need (Roblox shift lock = LShift, label now says so; a duplicate `slowtap` block was removed because it generated identical code). Group **Background**: `msgclick` (PostMessage WM_LBUTTONDOWN/UP, no mouse move), `msgkey` (WM_KEYDOWN/UP via GetKeyVK), `bgscroll` (ControlClick WheelUp/Down, position built as `"x" X " y" Y` so values can never break the quotes), `bgtext` (ControlSendText), `wwaitt` (`found := WinWait(win, , s)` with its own importer rule because the generic `set` rule would swallow it). Existing: bgclick, csend, wwait, whide, runh. **Options** (Settings dialog + header round trip): `SET.notray` -> `#NoTrayIcon`, `SET.prio` -> `ProcessSetPriority "Low|BelowNormal|AboveNormal|High"` (a hand-written `ProcessSetPriority("High")` is read as the option), button "Use game-friendly input" sets `sm:'Event'`, `kd:30`, `md:10`. **Templates**: 'Minecraft / Roblox: turn the camera', 'Roblox: toggle shift lock', 'Auto clicker for games', 'Click a window in the background'. **Program locations (user reported a wrong compiler stuck forever)**: root cause was that any picked file was saved unvalidated and a saved path always "exists" so the app never asked again. Now `COMP.looksLikeAhk/looksLikeCompiler` validate picks (and AutoHotkey must report version 2), a saved path that does not look right is ignored automatically, IPC `tool-paths`/`tool-set`/`tool-reset` (reset clears only the chosen key), Help > Program locations shows the paths in use with Choose / Reset to automatic, a failed compile names the compiler it used and points at the reset. **Try it**: Sim has pretend one-line logs for NexoMoveBy/NexoLook/NexoGameClick and `GetKeyVK`; a loop that sleeps and hits the step limit (the normal toggle auto-clicker pattern, which the single-threaded simulator can never turn off) is now an info line "still running", only a loop with no Sleep is an error.
**Not verifiable here**: real games. Some games or anti-cheat reject injected input; AutoHotkey input is flagged as injected. Tests: selftest section 33, simtest soft-stop, screentest Program locations, maintest/utiltest tool paths.
